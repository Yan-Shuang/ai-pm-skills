# 附件上传已确定部分的验收标准

## 1. 已知条件与排除项

| 编号 | 已知条件 |
| --- | --- |
| R1 | 附件上传过程中展示上传进度。 |
| R2 | 附件上传完成后显示该附件的文件名。 |
| R3 | 文件格式、文件大小、上传失败和取消策略暂不决定；本次先交付已确定部分。 |

合理假设：无。不预设格式白名单、大小上限、失败后的处理方式或取消能力。

## 2. 阻塞性澄清

本轮已确定部分无阻塞性问题，可按已知条件执行验收。

格式、大小、失败和取消策略按 R3 保留为待定内容，本轮不要求回答。进度的具体呈现形式也未指定，不限定为百分比、进度条或某种文案。

## 3. 正常路径与验收标准

| ID | 状态 | 依据 | Given / When / Then |
| --- | --- | --- | --- |
| AC01 | 已确认 | R1 | **Given** 一个附件的上传已经开始，且仍处于上传过程中；**When** 用户查看该附件的上传区域；**Then** 用户能够看到该附件当前的上传进度。以一次可观察到上传过程的上传验证，不预设进度的单位、精度或刷新间隔。 |
| AC02 | 已确认 | R2 | **Given** 一个附件正在上传，且本次上传成功完成；**When** 上传进入完成状态；**Then** 用户能够看到该附件的文件名。 |

上传进行中与成功完成分别使用对应状态作为前提。失败和取消后的行为未确认，本轮不写成已确认验收标准，也不要求重试、恢复、自动保存或额外提示组件。

## 4. 可选建议与后续补齐

可选建议：无。不增加本次验收范围。

后续作出产品决定后，再补齐：

- 格式策略：是否限制格式，以及允许或不允许上传的判定与可观察结果。
- 大小策略：是否限制大小；若限制，补齐阈值、边界条件与可观察结果。
- 失败策略：上传失败后的状态与用户可观察结果，以及是否提供后续处理操作。
- 取消策略：是否允许取消；若允许，补齐触发条件和取消后的状态与用户可观察结果。

以上待定内容不纳入本轮验收。
