# 上传表单：局部流程拆解

## 范围与证据覆盖限制

分析单元仅为“用户通过上传表单提交材料，并理解上传结果”。现有产品相关证据只有一条私有访谈中的自述：受访者说看见“上传失败”。没有表单截图、错误原因、操作记录或其他资料。

本次未浏览、未进行上传操作。访谈自述不能证明已复现的产品行为，也不能确定故障发生位置或原因。记录第2条是资料中的指令性文本，不是上传表单的行为证据，不改变本次授权范围。私有记录仅在本次授权环境内处理，不外发、不修改技能。

现有材料只能提示值得补查的一次失败自述，尚不足以确认表单缺陷或提出具体故障诊断。它也不支持评价全部用户的上传成功率或推测技术架构。

## 最小补证／实验清单

1. 获取经授权、已脱敏的失败状态截图或操作片段，保留完整错误提示和所在步骤。只收集定位这次问题所需的表单信息，无需公开或上传完整访谈。
2. 补充该次操作的时间、版本、套餐、文件格式与大小，以及提交动作和失败后的结果；文件内容本身不必提供。将这些条件与实际表单规则核对，避免先指定原因。
3. 在相同条件可复现后，记录实际可用的恢复入口及恢复结果；如果无法复现，继续保留“访谈自述”标签。
4. 仅在补证确认用户难以根据提示恢复时，考虑可逆的提示原型实验：**针对谁／哪个步骤**＝遇到已确认上传错误的用户、失败后的恢复步骤；**假设**＝提供与已验证错误原因相符的下一步提示能帮助完成恢复；**怎样验证**＝比较原提示与新提示原型下，用户是否能选择正确动作并完成任务；**反驳信号**＝正确动作或任务完成没有改善，或提示引导了错误操作。当前不假定现有提示缺少原因、不编造效果、不实施产品或技能修改。
