# 成员列表导出：需求与验收标准

## 1. 已知条件与排除项

- **R1**：管理员可以导出成员列表。
- **R2**：所有非管理员角色均不能导出成员列表。
- **R3**：本次不做批量操作。
- **R4**：本次不做定时任务。

**合理假设：无。** 不预设导出字段、数据范围、文件格式或错误处理政策。

## 2. 阻塞性澄清

这些问题不阻塞已确认的权限规则，但会阻塞对应的数据和边界验收：

- **Q1**：导出哪些成员、包含哪些字段？导出范围是否受当前筛选或分页影响？阻塞 **AC03** 的内容准确性判定。
- **Q2**：导出结果采用什么格式、通过什么方式获取？阻塞 **AC04** 的交付形式判定。
- **Q3**：成员列表为空时，导出应得到什么结果：允许导出空列表、阻止导出，还是其他行为？阻塞 **AC05** 的空态判定。
- **Q4**：导出执行失败时，管理员应看到什么结果或状态？阻塞 **AC06** 的失败处理判定；不预设自动重试或恢复。

批量操作和定时任务已明确排除，本轮不需要决定其行为。

## 3. 正常及相关异常路径与验收标准

| ID | 状态 | 依据 | Given / When / Then |
| --- | --- | --- | --- |
| **AC01** | 已确认 | R1 | **Given** 当前角色为管理员，成员列表包含已知测试成员，测试环境满足正常导出条件；**When** 管理员发起成员列表导出；**Then** 系统允许并完成此次导出，管理员能够获取成员列表的导出结果。具体数据内容按 AC03、交付形式按 AC04 确认。 |
| **AC02** | 已确认 | R2 | **Given** 当前角色为任一非管理员角色，成员列表包含相同测试成员，测试环境满足正常导出条件；**When** 该角色尝试发起成员列表导出（若存在可直接触发导出的请求方式，也通过该方式测试）；**Then** 该角色不能完成导出，也不能获取此次操作的导出结果。对系统已有的每一种非管理员角色分别执行。 |
| **AC03** | 待确认 | R1、Q1 | **Given** 当前角色为管理员，测试数据包含范围内和范围外成员以及待核对字段，测试环境满足正常导出条件；**When** 管理员发起成员列表导出；**Then** 导出记录与字段符合 Q1 确认的范围和字段规则。若范围遵循筛选或分页，按确认的规则核对；若导出全部成员，则核对全部成员。范围外的记录不应被导出。 |
| **AC04** | 待确认 | R1、Q2 | **Given** 当前角色为管理员，成员列表非空，测试环境满足正常导出条件；**When** 管理员发起成员列表导出；**Then** 通过 Q2 确认的方式获取结果，结果符合确认的格式，并能按该格式读取。 |
| **AC05** | 待确认 | R1、Q3 | **Given** 当前角色为管理员，按已确认导出范围得到的成员列表为空，测试环境不存在执行故障；**When** 管理员发起成员列表导出；**Then** 若 Q3 确认允许空列表导出，则获得符合空列表规则的结果；若确认阻止导出，则操作被阻止并呈现确认的空态结果；其他政策按 Q3 的答案补齐。 |
| **AC06** | 待确认 | R1、Q4 | **Given** 当前角色为管理员，成员列表非空，测试环境已设置可复现且会使此次导出无法完成的故障条件；**When** 管理员发起成员列表导出；**Then** 呈现 Q4 确认的失败结果或状态。具体表现待确认后补齐，不默认要求重试、恢复或新增提示组件。 |

AC01 与 AC02 使用相同的正常环境，以角色差异验证权限；AC06 使用明确故障条件，与成功路径的前提互斥。

## 4. 可选建议与后续补齐

**可选建议：无。** 不增加本次范围之外的功能。

Q1–Q4 确认后，补齐对应标准的具体输入数据、预期记录与字段、结果格式及空态和失败状态。批量操作、定时任务继续排除在本次验收之外。

**只有 AC01、AC02 可直接进入当前验收清单；AC03–AC06 待关联问题确认后再进入验收清单。**
