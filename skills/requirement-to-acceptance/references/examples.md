# 可复制示例

以下是预先编写、AI辅助生成的教学示例。验收对象是外部可观察的行为，不强制代码实现。实际测试回答另有记录。

## 1. 完整的小需求

输入：

```text
$requirement-to-acceptance
仅对当前选中的一条本地草稿提供删除。点击删除后先确认。
确认则草稿从列表消失；取消则保留。无选中草稿时删除不可用。
不需要回收站、批量删除或撤销。
```

输出示范：

```text
R1：只删除当前选中一条本地草稿。R2：先确认。
R3：确认后从列表消失；取消保留。R4：未选中时不可删除。
排除：回收站、批量删除、撤销。假设：无。阻塞问题：无。
路径：选中→删除→确认/取消；未选中→操作不可用。
AC1 [已确认，R1/R2] Given 已选中一条草稿，When 点击删除，Then 出现确认步骤，确认前草稿仍存在。
AC2 [已确认，R1/R3] Given 处于删除确认步骤，When 确认，Then 选中草稿从列表消失，其他草稿仍在。
AC3 [已确认，R3] Given 处于删除确认步骤，When 取消，Then 草稿仍在列表中。
AC4 [已确认，R4] Given 未选中草稿，When 查看删除入口，Then 删除操作不可用。
可选建议：无。可按已知条件执行验收。
```

## 2. 信息缺失，交付部分标准

输入：

```text
$requirement-to-acceptance
让管理员导出成员列表，其他角色不能导出。先不做批量操作和定时任务。
```

输出示范：

```text
R1：管理员可导出成员列表。R2：其他角色不可导出。
排除：批量操作、定时任务。假设：无。
Q1：导出哪些成员范围、字段和文件格式？阻塞AC2的输出核对。
Q2：空列表及导出失败时，应给什么可观察结果？阻塞AC3。
路径：管理员发起→导出成功；其他角色→不允许导出；空列表/失败→结果待定。
AC1 [已确认，R2] Given 当前角色不是管理员，When 尝试导出成员列表，Then 不生成成员导出结果。入口呈现形式不作限定。
AC2 [待确认，R1/Q1] Given 管理员且列表非空，When 发起导出，Then 得到文件；范围、字段与格式按Q1答案核对。
AC3 [待确认，Q2] Given 列表为空或导出失败，When 发起导出，Then 按Q2选择的空态/失败行为核对。
可选建议 O1：导出前展示范围摘要，供以后讨论，不纳入本次验收。
```

## 3. 明示条件与假设分离

输入：

```text
$requirement-to-acceptance
增加订单搜索，输入订单号能找到对应订单。只做精确搜索，不做模糊搜索。
其他信息暂时没有，先给可讨论的验收草案。
```

输出示范：

```text
R1：按订单号找到对应订单。R2：仅精确搜索；排除模糊搜索。
A1：草案按“输入内容与订单号完全相同”解释精确匹配，大小写/前后空格规则待确认。
Q1：搜索可见订单的权限范围是什么？阻塞AC1的可搜索范围。
Q2：无匹配、空输入的可观察结果是什么？阻塞AC2/AC3。
Q3：精确匹配是否去除前后空格、区分大小写？阻塞AC4。
AC1 [待确认，R1/Q1] Given 输入目标订单号且该订单处于确认后的可见范围，When 执行搜索，Then 结果包含对应订单。
AC2 [待确认，Q2] Given 没有精确匹配订单，When 搜索，Then 按确认后的无结果行为核对。
AC3 [待确认，Q2] Given 输入为空，When 发起搜索，Then 按确认后的空输入行为核对。
AC4 [假设草案，R2/A1/Q3] Given 存在订单号AB12，When 搜索AB，Then 不将AB12作为匹配结果；规范化规则另待确认。
可选建议：无。不得把模糊搜索纳入验收。
```
